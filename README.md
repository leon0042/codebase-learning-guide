# codebase-learning-guide

一个**通用**的 **Agent Skill**（智能体技能）：把一个陌生的项目文件夹交给它，它会先通读项目、摸清你的水平，然后按关卡带你读懂它。

遵循 [Agent Skills 开放标准](https://agentskills.io/specification)，可在 ZCode / Claude Code / Codex / Gemini CLI / Cursor / OpenCode / GitHub Copilot 等兼容工具上使用。

> **一句话概括**：它不是"技术手册"，而是**教学法 + 阅读路线**——负责"怎么教、按什么顺序教、怎么判断你真的会了"，关于"这个项目是什么样"的每一句话都现场从代码里读出来，不预置、不照抄 README。

**不限语言、不限项目类型**：嵌入式固件、后端服务、前端应用、CLI 工具、库、数据管道、编译器等都能用；连没有可执行代码的纯文档型项目（提示词库、技能包、配置仓库）也有对应路线。

---

## 一、它解决什么问题

拿到一个陌生项目时，典型的困境是四个：

1. **不知道从哪开始** —— 文件太多，不敢下手，也不知道哪些可以先跳过（比如哪个目录是第三方库，根本不用读）。
2. **不知道自己缺什么** —— 读了 README 还是没搞懂架构，也分不清"看懂了"和"真的会了"。
3. **不知道要学到什么程度** —— 是只想了解框架，还是要能读懂关键实现、能自己改？目标不同，路线差别很大。
4. **问题问不到点上** —— 提问太笼统，得到的答案也用不上。

这个 skill 把这几件事变成固定流程：**先通读项目建地图 → 摸清你的水平 → 你来定学多深 → 逐关引导 → 随时答疑 → 记录进度**。

README 说的是"项目想成为什么"，代码说的是"它现在是什么"——两者经常不一致。本 skill 一律以代码为准，并**把发现的文档与代码冲突单独列出来**，那往往正是"看完文档却没懂"的原因。

## 二、适用对象与前置条件

**适用**：

- 刚拿到一个项目，想系统看懂它
- 想入门某个技术栈，用真实项目当教材
- 之前只在单个文件里打转，想建立全局结构感
- 想确认自己该从哪一层开始读、该学到什么深度

**前置条件**：

| 条件 | 说明 |
|---|---|
| 一个项目目录 | 本地路径即可，不需要联网、不需要项目能跑起来 |
| Python 3.7+（可选） | 仅扫描脚本 `scripts/project_scan.py` 需要，纯标准库、无第三方依赖 |
| 支持选项式提问的工具 | 诊断环节默认用 `AskUserQuestion` 类工具；没有该工具时会降级为正文编号选项，不会卡住 |

**不需要**：不需要项目自带任何学习文档或教学技能。这一点和项目专用的学习技能不同——本 skill 会现场生成路线。

> ⚠️ **默认只读。** 整个学习过程不会修改被学习项目的源码。学习笔记写在项目内的 `.codebase-learning/`（或项目不可写时写到家目录），首次创建时会提醒你加进 `.gitignore`。

## 三、安装

本仓库根目录**就是** skill 目录（含 `SKILL.md`），可直接 clone 到技能发现路径。

### 方式一：用户级安装（推荐，所有项目都能用）

```bash
git clone https://github.com/leon0042/codebase-learning-guide.git ~/.agents/skills/codebase-learning-guide
```

Windows PowerShell：

```powershell
git clone https://github.com/leon0042/codebase-learning-guide.git "$env:USERPROFILE\.agents\skills\codebase-learning-guide"
```

装好后在**任意项目**里说"带我看懂这个项目"就会触发。

### 方式二：项目级安装（只对某个仓库生效）

```bash
# 在目标工程根目录执行
mkdir -p .agents/skills
git clone https://github.com/leon0042/codebase-learning-guide.git .agents/skills/codebase-learning-guide
```

### 各工具的发现路径

| 工具 | 用户级 | 项目级 |
|---|---|---|
| ZCode | `~/.zcode/skills/`、`~/.agents/skills/` | `.zcode/skills/`、`.agents/skills/`（从当前目录向上到仓库根，每层都扫） |
| Codex CLI / Gemini CLI / Cursor / OpenCode | `~/.agents/skills/` | `.agents/skills/` |
| GitHub Copilot | `~/.agents/skills/` | `.agents/skills/`、`.github/skills/`、`.claude/skills/` |
| Claude Code | `~/.claude/skills/`（**不扫** `.agents/`） | `.claude/skills/`（需 symlink/junction 桥接） |

> **Claude Code 用户注意**：它不扫描 `.agents/`，需要桥接。Windows 上用 Junction（不需要管理员权限）：
> ```powershell
> # 用户级
> New-Item -ItemType Junction -Path "$env:USERPROFILE\.claude\skills\codebase-learning-guide" -Target "$env:USERPROFILE\.agents\skills\codebase-learning-guide"
> ```
> macOS / Linux 上 `ln -s` 即可。

### 安装后自检

```bash
python ~/.agents/skills/codebase-learning-guide/scripts/project_scan.py <任意项目路径> --top 5
```

能输出一段 JSON 骨架即就绪。

## 四、怎么用

装好后直接说人话，把项目路径给它：

```text
带我学一下 D:\work\my-new-project
我刚拿到这个项目，从哪开始看？
这个仓库怎么入门，我是第一次接触 Go
我之前只在单个文件里改过代码，想搞懂整体架构
顺便问一下，这个文件里那两行的先后关系是什么？
```

### 推荐开场

最简单也最有效的一句：

```text
带我看懂 <项目路径>
```

它会立刻开始四步流程，**在扫描和诊断完成之前不会讲任何架构**。

> **重要**：学生没说路径时它会主动问你要，不会在当前目录瞎扫。所以第一次用时把路径给全。

### 它不会做什么

- 不改代码、不修 bug、不重构、不部署
- 不在你还没到动手那一关时代替你改代码
- 不回答与项目无关的通用编程问题（那不在学习路线里）
- 不把 README 念一遍给你听

## 五、它怎么工作

### 快速开始（学生丢来一个项目文件夹时）

```
① 扫描     project_scan.py 一次拿到语言分布、顶层结构、构建清单、入口候选、文档清单
② 备课     读项目内 AGENTS.md / README / 构建清单 → 追一条主链路 → 写出项目地图
③ 摸底定档 选项式提问 3–4 题 → 行为化复验校正 → 你选「了解框架 / 深入研究」
④ 进入引导 从第 1 关开始，每关：讲 → 问 → 验
```

### 五步流程

```
第 0 步 备课   扫描 + 读文档与构建清单 + 追一条主链路 → 项目地图   ← 新项目必做
第 1 步 摸底   选项式提问，诊断四个维度的知识水平                 ← 新学生必做
第 2 步 定档   选深度（了解框架 / 深入研究）+ 定起点关卡
第 3 步 引导   六关骨架：讲 → 问 → 验，通关才往下走               ← 主体
第 4 步 答疑   你随时提问，结合当前关卡与深度回答
第 5 步 收尾   回写学习档案（进度 / 缺口 / 下一步）
```

第 0、1 步只在第一次做。之后每次会话从"轻量复检"开始：读状态文件 + 确认这次推进什么，不重新全量备课。

### 六关骨架（每关都按项目现场实例化）

| 关 | 目标 | 完成判据（做到才算通关） |
|---|---|---|
| 1 意图 | 一句话说清这项目解决什么问题、给谁用 | 不看 README 能自己说出来 |
| 2 骨架 | 顶层模块职责 + 程序从哪启动 + 外部依赖 | 能画出模块图并指出入口文件 |
| 3 数据 | 核心数据结构 / 状态是什么，怎么在系统里流动 | 能说出"改这个字段会影响什么" |
| 4 主干 | 一条代表性链路的完整调用路径 | 能自己从入口走到出口，不靠提示 |
| 5 关键 | 项目里最聪明 / 最危险的 1–2 处实现 | 能说出"为什么这么写，换个写法会怎样" |
| 6 动手 | 做一次受控的小改动，或写个观察脚本 | 改动生效 / 脚本跑通，且能解释结果 |

### 两档学习深度（你来选，它不替你决定）

| 档位 | 你想要的 | 终点关卡 | 典型节奏 |
|---|---|---|---|
| **了解框架** | 知道项目由哪些部分组成、大致怎么跑、改动会牵动什么 | 第 4 关 | 1–2 次会话 |
| **深入研究** | 读懂关键实现、能自己定位与修改、能判断改动的后果 | 第 6 关 | 多次会话 |

拿不定主意时默认"了解框架"——**先建立全局再决定深挖哪里**。反过来（一头扎进某个模块再回头看全局）是初学者最容易迷路的方式。**档位中途可以改**，随时说。

### 摸底诊断：四个维度

不问你"你懂不懂 X"这种开放式问题——初学者往往给不出有用答案，因为不知道该怎么描述自己的水平。**给具体选项，你只需要认领**：

| 维度 | 问的是什么 |
|---|---|
| D1 语言与惯用法 | 项目主语言的语法、惯用写法、标准库 |
| D2 工具链 | 构建、运行、调试、依赖管理、版本控制 |
| D3 领域知识 | 这个项目解决的问题属于哪个领域 |
| D4 代码阅读能力 | 多文件架构、抽象层次、异步与并发、测试 |

**题目由项目现场生成**，不用通用题库——问与这个项目无关的问题是浪费时间。

> **一个实测出来的关键机制**：自评会**系统性偏高**（"能看懂别人的实现"常常实际等于"每个词都认识，但读不懂在干什么"）。所以定档前会出 1–2 道**行为化复验题**，拿项目真实代码让你当场答；答不上就降档，并说明"这道题实际需要先知道 X，补上再往下走"。这是校正，不是考试。

### 每一步都有判据，通关才往下走

**完成判据是你能自己说出来，不是"听它说过"。** 说不出来就换一种讲法重讲，不硬推。卡住时它用**最小提示阶梯**，从轻到重：

1. 指位置 ——"去看某个文件第 N 行附近"
2. 给问题 ——"如果那个变量是 0 会发生什么？"
3. 给类比 ——拿你已经懂的东西对照
4. 才给答案，并要求你复述

同一关连续两次没过，它会换讲法、拆细、然后**怀疑是自己的起点定高了**——而不是怪你。

## 六、扫描脚本

`scripts/project_scan.py` 是技能的确定性部分：一次调用拿到项目全貌，避免 agent 靠手工翻目录（那样会漏、会高估小文件、还浪费大量工具调用）。

```bash
python scripts/project_scan.py <项目路径> --top 20
```

| 参数 | 作用 |
|---|---|
| `--top N` | 每类列表最多输出多少条（默认 20，设小可省上下文） |
| `--max-depth N` | 目录树展开深度（默认 2） |
| `--exclude a,b` | 额外排除的目录，例如 `lib,vendor,third_party` |
| `--no-git` | 跳过 git 信息收集 |

输出是单个 JSON 对象，主要字段：

| 字段 | 用来判断 |
|---|---|
| `summary.top_languages` | 主语言是什么，单语言还是混合 |
| `largest_top_level_dirs` | 文件数大头在哪 —— **能看出哪些是第三方库** |
| `skipped_top_level_dirs` | 哪些目录被跳过了（备份、构建产物、依赖缓存） |
| `build_and_dependency_manifests` | 用什么构建、依赖什么、怎么跑 |
| `entry_point_candidates` | 程序从哪进（文档型项目则给出事实源） |
| `docs_and_notes` | 有哪些文档可读 |
| `largest_source_files` | 哪些文件最重，通常就是要点所在 |
| `git.recently_changed_top_level` | 开发热点 —— 最该先读懂的地方 |

退出码：`0` 成功 / `1` 参数错误 / `2` 路径不存在或不是目录。

> **一个实测教训（脚本已内置处理）**：有的工程 `lib/` 里躺着 Eigen、MAVLink、FreeRTOS 这类第三方库。实测中一个实际 **1.8 万行**的工程被报成 **37 万行**——差 20 倍，会直接毁掉"这项目多大、要学多久"的判断。技能要求交叉核对 `largest_top_level_dirs` 与该目录下的构建文件/许可证，确认是 vendor 后用 `--exclude` 重扫。

## 七、文件结构

```
codebase-learning-guide/
├── SKILL.md                       # 主流程：四条铁律 + 五步流程 + 六关骨架（约 320 行）
├── references/
│   ├── 备课指南.md                # 第 0 步：怎么在零背景前提下读懂陌生项目
│   ├── 诊断与定档.md              # 第 1、2 步：出诊断题、自评复验、定起点与深度
│   ├── 引导与答疑.md              # 第 3、4 步：六关话术、最小提示阶梯、五种答疑类型
│   └── 产出模板.md                # 项目地图与学习档案模板
├── scripts/
│   └── project_scan.py            # 项目机械扫描（纯标准库、只读、幂等）
├── README.md                      # 本文件
├── LICENSE                        # MIT
└── .gitattributes                 # 换行符归一化
```

**渐进披露设计**：`SKILL.md` 只放流程与铁律，细节按需加载 4 份参考文件——避免一次塞爆上下文。

### 学习过程产生的文件

学习笔记写在**被你学习的项目**里，不在技能目录里：

```
<你的项目>/.codebase-learning/
├── project-map.md     备课产物：模块职责表、入口、核心数据结构、主链路、待深挖点、文档冲突清单
└── progress.md        学习档案：学生画像、路线进度、会话记录、待补清单
```

项目不可写（只读挂载、别人的仓库、有只读约束）时，自动退回到 `<用户主目录>/.codebase-learning/<项目名>/`。**技能升级不会影响这些档案**，这是特意这样设计的。

## 八、设计原则

1. **教学法 + 路由，不预置项目知识。** 关于"这个项目是什么样"的每一句话都现场从代码读出来。凭印象讲代码是这类教学最常见的失败方式——记错文件名，你按它的话去翻找不到，信任一次就没了。
2. **结论必须落到文件与行号。** 讲任何机制都给 `路径:行号`。你学的是一个具体系统，不是教科书上的抽象原理。
3. **判据是"你能说出来"，不是"它讲过"。** 点头和沉默都不是判据。
4. **引导优先于告知。** 你卡住时它先指路（该看哪个文件哪一段），而不是直接把结论丢过来——自己找到答案形成的心智模型牢固得多。
5. **默认只读。** 尤其在第 6 关之前不动你的项目。它改完你看懂了，那是它的理解，不是你的。

## 九、已知限制

- **需要 Python 才能用扫描脚本。** 没有 Python 时技能会退回手工翻目录——仍能工作，但会慢，且更容易漏掉隐藏目录和大文件。扫描结果里 `lib/` 型第三方库堆积的提示也会弱一些。
- **诊断依赖选项式提问工具。** 不支持的宿主会降级为正文编号选项；若你也无法实时回应，它会**声明假设并继续**，并把假设标为"未确认"记进档案，下次先核实——错误的画像会让整条路线都偏掉。
- **项目专用学习技能存在时以它为准。** 若某工程自带 `*-learning-guide` 之类的专用技能，它的路线（分层、判据、安全约束）更权威；本技能退为"通用阅读方法"的补充。两者路线编号不同时会做合并映射，不会让你同时看到两套"第 N 关"。
- **大项目仍是分片备课。** 几十万行的项目不会一次通读，而是只对当前要教的那一块做完整备课，其余标"待探索"。地图上标 `待确认` 的地方是真的没核实——它不会用模糊表述蒙过去。
- **没有可读源码时不会硬凑。** 纯二进制、混淆代码、代码生成产物，它会如实说明并给替代路线（读文档、读类型定义、读测试用例），而不是编一份看着完整的地图。
