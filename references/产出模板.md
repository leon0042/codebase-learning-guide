# 产出模板

学习过程产生两个文件，都放在 `<项目根>/.codebase-learning/`：

| 文件 | 何时写 | 谁看 |
|---|---|---|
| `project-map.md` | 第 0 步备课结束 | 你自己（备课笔记，也是给学生看的路标） |
| `progress.md` | 第 5 步收尾，每次会话更新 | 下一次会话的你自己 |

**这些是工作文件，不是交付文档。** 表格化、可查、宁短勿长。不要写成散文。

---

## project-map.md 模板

```markdown
# <项目名> 项目地图

> 由 codebase-learning-guide 技能备课生成，最后更新：<日期>
> 标注 `待确认` 的地方表示未核实，讲之前请先确认。

## 一、这个项目是什么

<两三句话：解决什么问题，给谁用，最核心的一个取舍是什么。>

## 二、技术栈与运行方式

| 项 | 内容 |
|---|---|
| 主语言 | |
| 构建系统 | |
| 关键依赖 | |
| 怎么跑起来 | `<命令>` |
| 怎么跑测试 | `<命令>` / 无 |

## 三、模块职责表

| 模块/目录 | 职责（一句话） | 关键文件 |
|---|---|---|
| `路径/` | | `路径/文件:行` |

## 四、入口与启动流程

入口文件：`路径/文件:行`

```
1. <步骤> → 路径/文件:行
2. <步骤> → 路径/文件:行
```

## 五、核心数据结构

| 结构 | 定义位置 | 作用 |
|---|---|---|
| `<类型名>` | `路径/文件:行` | |

## 六、主链路（一条走通的路径）

链路名称：<例如"一次 HTTP 请求""一个控制周期">

```
入口 → A(文件:行) → B(文件:行) → C(文件:行) → 输出
每步一句话职责：
- A:
- B:
- C:
```

## 七、五个值得深挖的点

1. `<文件:行>` — 为什么值得看
2. …
3. …
4. …
5. …

## 八、文档与代码冲突清单

项目文档（README、注释、设计文档）与实际代码不一致的地方。**这类冲突是教学中最有价值的素材**——它让学生建立"以代码为准"的意识，也直接解释了为什么他"看完文档还是没懂"。

| 文档说 | 代码实际 | 位置 |
|---|---|---|
| `<README 里的说法>` | `<真实行为>` | `<文件:行号>` |

没有发现就写"未发现"。

## 九、待确认 / 未探索区域

- [ ] <没看明白或没看的内容，标注原因>
```

### 填充要点

- **第四、六节必须给行号。** 没有行号的地图在讲解时无法核对，学生会白跑。
- **第六节是整份地图的骨架。** 主链路走不通，说明备课没做完；走通了但给不出行号，说明是猜的。
- **第七节是第 5 关的取材库。** 备课途中遇到"这段很精妙"或"这段很危险"就记下来，别当时就陷进去研究。
- **第八节是"以代码为准"的教材。** 每发现一处文档与代码不符就记一条；讲解时挑一两条讲给学生，比任何说教都有效。
- **第九节要诚实。** 没看的部分就是没看，标出来。用模糊表述蒙过去会在讲解时露馅。

## progress.md 模板

```markdown
# <项目名> 学习档案

## 学生画像（首次诊断结果）

诊断日期：<日期>

| 维度 | 自评档位 | 依据 |
|---|---|---|
| D1 语言与惯用法 | <1-4> | <学生原话或题目> |
| D2 工具链 | | |
| D3 领域知识 | | |
| D4 代码阅读能力 | | |

**结论：** 起点 = <关卡 N>；深度 = <了解框架 / 深入研究>
**依据：** <为什么这样安排>
**需要先补的：** <前置内容，或"无">

## 路线与进度

| 关 | 项目化后的主题 | 状态 | 完成判据 |
|---|---|---|---|
| 1 意图 | | 未开始 / 进行中 / 已通关 | |
| 2 骨架 | | | |
| 3 数据 | | | |
| 4 主干 | | | |
| 5 关键 | | | |
| 6 动手 | | | |

## 会话记录

### <日期> 第 N 次会话

- **本次目标：**
- **实际完成：** <具体到掌握点，不要写"学了 X">>
  - 例：能说出环形缓冲读写指针的推进规则，但说不清缓冲区满时丢的是哪一帧
- **暴露的缺口：** <需要回头补的点；没有就写"无">
- **本次有效的讲法：** <哪种解释方式他接得最快——下次沿用；没有就写"无">
- **下一步：**

## 待补清单

- [ ] <要回头补的知识点>
```

### 填充要点

- **"实际完成"必须具体到可续接。** 判断标准：下次会话读这一行，你能不能直接接着讲？不能就是写得太粗。
- **"本次有效的讲法"经常被忽略，但很值钱。** 同一个概念，用类比讲通了还是用代码讲通了，下次直接复用，省一整轮。
- **进度变更要记录。** 学生中途调整深度档位、或起点重定，都在会话记录里写明原因，避免下次自己看不懂为什么路线和诊断结论不一致。
- **不要为仪式感编造。** 只讲清半关就写半关。

## 存放位置与 .gitignore

**位置只按这一条规则定：**

1. **首选** `<被学习的项目根>/.codebase-learning/`，首次创建时提醒学生加一行：

```gitignore
# 本地学习笔记，不入库
.codebase-learning/
```

2. **项目不可写时**（只读挂载、别人的仓库、沙箱限制）退回 `<用户主目录>/.codebase-learning/<项目目录名>/`；同名冲突时在目录名后加项目根完整路径去盘符分隔符后的前 8 个字符（`D:\work\backend` → `backend-Dworkback`）。**不要用随机数或时间戳**，否则下次会话算不出同一目录名，档案就找不回来了。

**不要放进技能自己的目录**——技能升级或被重装时可能整个被替换，学习档案会一起丢；多人共用同一个技能安装时还会互相覆盖。
